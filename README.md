# DayZ Manager

Windows-приложение (.NET 8 / WPF) для запуска клиента и выделенного сервера DayZ отдельно для
веток **Stable** и **Experimental**, с редактором `serverDZ.cfg`, выбором миссии и отдельным окном
просмотра логов клиента/сервера в реальном времени. Иконка и оформление — под DayZ.

## Сборка

```
dotnet build DayZManager.sln
```

Готовый exe: `src\DayZLauncher.App\bin\Debug\net8.0-windows\DayZManager.exe`. Внутренние имена
проектов/namespace остались `DayZLauncher.*` (см. «Внутреннее устройство» ниже) — переименован
только сам продукт: exe, заголовки окон, иконка.

Для отдельного портативного exe, который реально работает будучи скопированным один файл куда
угодно (например на рабочий стол) — без установленного .NET и без соседних DLL:

```
dotnet publish src\DayZLauncher.App\DayZLauncher.App.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -p:DebugType=none -o publish
```

Без `IncludeNativeLibrariesForSelfExtract=true` WPF всё равно оставляет рядом с exe несколько
нативных DLL (D3DCompiler/PenImc/PresentationNative/vcruntime140/wpfgfx) - `PublishSingleFile` сам
по себе их не упаковывает. С этим флагом они зашиты внутрь `DayZManager.exe` и при первом запуске
самораспаковываются во временную папку - снаружи остаётся только один файл. `EnableCompressionInSingleFile`
сжимает их внутри exe (иначе результат — под 160 МБ, со сжатием — около 68 МБ). `DebugType=none`
убирает `.pdb` из папки публикации.

Результат — `publish\DayZManager.exe` (~68 МБ, весь рантайм внутри) - его можно скопировать
куда угодно (например на рабочий стол) одним файлом, ничего рядом не нужно.

## Первый запуск

Окно программы центрируется по экрану (на всех последующих запусках — вместо этого восстанавливается
последняя сохранённая позиция). Настройки (`settings.json`) при этом ещё не существуют, поэтому
программа сразу предлагает диалог «Выполнить автоматический поиск установленных файлов игры
клиент/сервер?»:

- **Да** — ищет клиент и сервер через Steam для **обеих** веток сразу (тот же поиск, что и кнопка
  «Найти (Steam)» на вкладках, просто одним нажатием для всего).
- **Нет** — ничего не делает, пути остаются пустыми, задаются вручную через «Обзор...».

Диалог показывается только один раз, пока нет `settings.json` — то есть ещё и после «Сбросить
настройки и перезапустить» (см. ниже), это по сути тот же «первый запуск».

По умолчанию (на новом/сброшенном профиле) из параметров запуска включены только `-connect`/`-port`
(за счёт тумблера «Локальный сервер» у клиента) и `-doLogs`/`-adminLog` у сервера — остальные флаги
выключены, их включают вручную под свои нужды.

## Ветка Stable / Experimental

Переключается через меню «⋮» → «Ветка» (или пунктами в нём же) и влияет на **всё**: у Stable и
Experimental свои независимые пути к клиенту/серверу, свои моды, свой `serverDZ.cfg` и своя миссия.
Настройки сохраняются в `%AppData%\DayZManager\settings.json` между запусками.

Кнопка **«Найти (Steam)»** есть и на вкладке «Клиент» (ищет `DayZ_x64.exe`/`DayZ_BE.exe`), и на
вкладке «Сервер» (ищет `DayZServer_x64.exe`, а заодно рядом `serverDZ.cfg` и папку `profiles`, если
они там есть) — best-effort поиск по всем зарегистрированным библиотекам Steam (сначала находит сам
Steam через реестр или `Program Files (x86)\Steam`/`Program Files\Steam`, затем читает его
`libraryfolders.vdf`, где перечислены ВСЕ диски с играми, не только системный). Если не нашла — путь
указывается вручную.

## Верхняя панель

- **Левый угол** — меню «⋮»: «Настройки» (открывает боковую панель настроек), «Тема» (Тёмная/Светлая),
  «Ветка» (Stable/Experimental), «О программе».
- Рядом — «Запустить сервер», «Запустить клиент» и «Логи», одного размера, в одну линию. Пока процесс
  остановлен, наведение на его кнопку подсвечивает её зелёным (запустит); как только он запущен,
  надпись меняется на «Остановить ...» и наведение подсвечивает её красным (остановит). Под каждой —
  индикатор (точка + текст) «запущен»/«не запущен», учитывающий и процессы, запущенные не через саму
  программу (например напрямую из Steam).
- Кнопка «Запустить клиент» заблокирована, пока включена цепочка автозапуска (см. ниже) — но только
  пока клиент реально не запущен; как только он стартует (хоть автоматически, хоть иначе), кнопка
  разблокируется и превращается в «Остановить клиент».
- **Правый угол** — текущая ветка и версии клиента/сервера (читаются прямо из exe).
- Пока клиент или сервер запущены (у активной ветки), вкладки «Клиент»/«Сервер» целиком (включая
  сами заголовки вкладок — переключиться между ними тоже нельзя) затемняются и блокируются, одинаково
  для обеих, независимо от того, что именно из двух сейчас работает.

## Настройки программы (боковая панель, «⋮» → «Настройки»)

**Основное**
- Запускать вместе с Windows.
- Запускать программу свёрнуто.
- Разрешить программе сворачиваться в трей.
- По закрытию программы сворачивать в трей — доступно только вместе с предыдущим пунктом; если
  включено, кнопка «✕» на главном окне не закрывает программу, а прячет её в трей (как обычное
  сворачивание). Из трея: двойной клик или «Открыть» — вернуть окно, «Выход» — закрыть по-настоящему.

**Запуск**
- Запускать клиент после запуска сервера через (сек) — при включении старт сервера через указанную
  задержку следом запускает и клиент.
- Чистить логи клиента/сервера перед запуском (`.RPT`/`.log`/`.ADM`).
- Вайпать сервер перед запуском — удаляет `storage_1` (персистентность: базы, лут, позиции) внутри
  `<сервер>\mpmissions\<текущая миссия>\`, миссия берётся прямо из `template=` в `serverDZ.cfg`.
  Необратимо.
- Автоматически копировать ключи `.bikey` на сервер при выборе модов — срабатывает сразу при
  добавлении мода через «+ Добавить мод» (а не при запуске): если у выбранной папки есть подпапка
  `keys` с `*.bikey`, они тут же копируются в `<папка_сервера>\keys\`. `@Имя` из Workshop сюда не
  попадают — их ключи синхронизирует сам Steam.

**Горячие клавиши** — все глобальные (работают, даже если фокус у самой игры): аварийная остановка
клиента/сервера обеих веток (по умолчанию `Ctrl+J`), запуск сервера (`Ctrl+Shift+S`), запуск клиента
(`Ctrl+Shift+C`, недоступен, пока включена цепочка автозапуска). Чтобы поменять сочетание — кликнуть
в поле и нажать новую комбинацию.

Внизу панели — кнопка **«Сбросить настройки и перезапустить»** (подсвечивается красным при
наведении): удаляет `settings.json` и перезапускает программу с настройками по умолчанию (включая
диалог автопоиска при следующем запуске, как при первом старте).

## Вкладки

- **Клиент** — путь к `DayZ_x64.exe`/`DayZ_BE.exe`; флаги `-noSplash`/`-skipIntro`/`-world=empty`/
  `-noPause`/`-window`/`-scriptDebug`, `-cpuCount`, `-name` (отдельный профиль); список модов
  (общий с сервером, см. ниже); необязательное прямое подключение (`-connect`/`-port`/`-password`,
  с тумблером «Локальный сервер», который берёт `localhost` и порт текущего сервера); доп. аргументы
  и предпросмотр итоговой командной строки. У клиента нет собственного `-profiles` — DayZ сам решает,
  куда писать логи (см. «Окно логов» ниже).
- **Сервер** — всё в одном месте:
  - пути (`DayZServer_x64.exe`, `serverDZ.cfg`, `-profiles` — у каждого поля рядом с «Обзор...» есть
    квадратная кнопка с иконкой папки, открывающая указанный путь в проводнике);
  - сеть/производительность (`-port`/`-cpuCount`/`-limitFPS`/`-BEpath`);
  - два независимых списка модов и диагностические флаги (`-doLogs`/`-adminLog`/`-netLog`/
    `-scriptDebug`/`-filePatching`/`-freezeCheck`), доп. аргументы, предпросмотр командной строки;
  - **Конфигурация сервера** — быстрые поля почти для всех ключей верхнего уровня `serverDZ.cfg`
    (около 40 штук: `hostname`, `password`, `maxPlayers`, `verifySignatures`, `disableVoN`,
    `serverTime*`, `loginQueue*`, все диагностические `adminLog*`, `steamQueryPort` и т.д.) плюс
    RAW-текст файла в сворачиваемом блоке — оба представления синхронизированы в обе стороны. У
    каждого поля — своя галочка «есть ли такой ключ в файле вообще» (отсутствующий ключ = пусто/выкл,
    не «0» и не догадка по умолчанию); отметил — ключ добавляется со значением по умолчанию,
    снял — удаляется из файла целиком. Часть таких галочек (около 20: `hostname`, `password`,
    `maxPlayers`, `verifySignatures`, `disableVoN`, `serverTime*`, `loginQueue*` и другие ключи,
    которые должны присутствовать в конфиге всегда) заблокированы — их нельзя случайно убрать из
    файла.
  - **Миссия** — список папок из `<сервер>\mpmissions` в виде переключателей: отметил — миссия сразу
    прописана в `template=` класса `Missions\DayZ`, отдельной кнопки «Применить» не нужно.

Моды (`-mod`/`-serverMod`) добавляются через кнопку **«+ Добавить мод»** — открывается диалог выбора
папки; выбранная папка (например `D:\Modding\Source\TEST_EXP`) добавляется в список и показывается
по имени папки (`TEST_EXP`), с квадратной кнопкой-папкой (открыть в проводнике) и `✕` (удалить).
`-mod` общий для клиента и сервера — список один и тот же на обеих вкладках, и подписи над списками
об этом явно напоминают.

### Порядок аргументов командной строки

Не влияет на работу движка (порядок параметров не позиционный), но зафиксирован именно таким:

- **Клиент:** `-mod` → `-name` → `-connect`/`-port`/`-password` → `-cpuCount` → `-noSplash` →
  `-skipIntro` → `-world=empty` → `-noPause` → `-window` → `-scriptDebug`.
- **Сервер:** `-BEpath` → `-config` → `-profiles` → `-port` → `-cpuCount` → `-limitFPS` → `-mod` →
  `-serverMod` → `-doLogs` → `-adminLog` → `-netLog` → `-scriptDebug` → `-filePatching` →
  `-freezeCheck`.

## Окно логов

Отдельное немодальное окно (можно держать открытым и одновременно работать в основном окне) —
переключатель Клиент/Сервер, тип файла (`.RPT`/`.ADM`/`.log`/`.txt`), список файлов и потоковый
просмотр (tail) выбранного с автопрокруткой и фильтром по подстроке (фильтр применяется ко всему уже
загруженному тексту, а не только к новым строкам). Кнопки «Обновить список», «Открыть папку» и
«Удалить логи». Текст следует теме (тёмный/светлый). Состояние окна — позиция, размер и то, было ли
оно развёрнуто на весь экран — запоминается отдельно от главного окна и восстанавливается между
запусками; при первом открытии (пока ничего не сохранено) центрируется, как и главное окно.

Папки логов по умолчанию (если поле Profiles сервера не заполнено):
- Клиент Stable: `%LOCALAPPDATA%\DayZ`
- Клиент Experimental: `%LOCALAPPDATA%\DayZ Exp`
- Сервер: `<папка сервера>\profiles`

## Ограничения

- Автопоиск Steam проверяет путь по умолчанию (или из реестра) и его `libraryfolders.vdf` —
  нестандартные установки Steam, которые туда не попали, ищутся вручную через «Обзор...».
- Быстрые поля конфига сервера покрывают ключи верхнего уровня из `serverDZ.cfg`; более сложные
  блоки (например, кастомные классы) редактируются через RAW-текст.
- Иконка приложения — `assets/app.ico`, замените файл, если нужна другая.
