# DayZ Manager

Windows-приложение (.NET 8 / WPF) для запуска клиента и выделенного сервера DayZ отдельно для
веток **Stable** и **Experimental**, с редактором `serverDZ.cfg`, выбором миссии и отдельным окном
просмотра логов клиента/сервера в реальном времени. Иконка и оформление — под DayZ.

## Сборка

```
dotnet build DayZManager.sln
```

Готовый exe: `src\DayZLauncher.App\bin\Debug\net8.0-windows\DayZManager.exe`. Внутренние имена
проектов/namespace остались `DayZLauncher.*` (см. «Внутреннее устройство» ниже) — переименован
только сам продукт: exe, заголовки окон, иконка.

Для отдельного портативного exe, который реально работает будучи скопированным один файл куда
угодно (например на рабочий стол) — без установленного .NET и без соседних DLL:

```
dotnet publish src\DayZLauncher.App\DayZLauncher.App.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=None -p:EnableCompressionInSingleFile=true -o publish
```

Без `IncludeNativeLibrariesForSelfExtract=true` WPF всё равно оставляет рядом с exe несколько
нативных DLL (D3DCompiler/PenImc/PresentationNative/vcruntime140/wpfgfx) - `PublishSingleFile` сам
по себе их не упаковывает. С этим флагом они зашиты внутрь `DayZManager.exe` и при первом запуске
самораспаковываются во временную папку - снаружи остаётся только один файл.

Результат — `publish\DayZManager.exe` (~70 МБ, весь рантайм внутри) - его можно скопировать
куда угодно (например на рабочий стол) одним файлом, ничего рядом не нужно.

## Переключатель Stable / Experimental

Вверху окна — переключатель ветки. Он влияет на **всё**: у Stable и Experimental свои независимые
пути к клиенту/серверу, свои моды, свой `serverDZ.cfg` и своя миссия. Настройки сохраняются в
`%AppData%\DayZManager\settings.json` между запусками.

При первом запуске (пока нет `settings.json`) пути пустые — программа предлагает выполнить
автопоиск установленных клиента/сервера через Steam (диалог «Да/Нет»); согласившись, пути для
обеих веток заполняются автоматически. Отказаться и указать пути вручную через «Обзор...» тоже
можно, как и повторить поиск позже кнопкой «Найти (Steam)».

Кнопка **«Найти (Steam)»** есть и на вкладке «Клиент» (ищет `DayZ_x64.exe`), и на вкладке «Сервер»
(ищет `DayZServer_x64.exe`, а заодно рядом `serverDZ.cfg` и папку `profiles`, если они там есть) —
best-effort поиск по всем зарегистрированным библиотекам Steam (сначала находит сам Steam через
`Program Files (x86)\Steam` или `Program Files\Steam`, затем читает его `libraryfolders.vdf`, где
перечислены ВСЕ диски с играми, не только системный). Если не нашла — путь указывается вручную.

## Верхняя панель

- **Левый угол** — «Запустить сервер», «Запустить клиент» и «Логи», одного размера, в одну линию.
  Пока процесс остановлен, наведение на его кнопку подсвечивает её зелёным (запустит); как только
  он запущен, надпись меняется на «Остановить ...» и наведение подсвечивает её красным (остановит).
  Никаких отдельных крестиков.
- **Правый угол** — ветка (Stable/Experimental) и статусы «Клиент: .../Сервер: ...» друг над другом.
- **Настройки** — сворачиваемая панель прямо под кнопками (не отдельное окно и не кнопка ⚙ - их
  убрали): тема, запуск клиента после сервера (с задержкой в секундах), очистка логов клиента и
  сервера перед запуском, Wipe server, копирование ключей модов (см. ниже). Все переключатели -
  тумблеры, не галочки.
- Окно программы (положение и размер) запоминается между запусками.

Моды (`-mod`/`-serverMod`) добавляются через кнопку **«+ Добавить мод»** - открывается диалог
выбора папки; выбранная папка (например `D:\Modding\Source\TEST_EXP`) добавляется в список и
показывается по имени папки (`TEST_EXP`), с `✕` для удаления. `-mod` общий для клиента и сервера -
список один и тот же на обеих вкладках.

## Вкладки

- **Клиент** — путь к `DayZ_x64.exe`/`DayZ_BE.exe`, флаги
  `-noSplash/-skipIntro/-world=empty/-noPause/-window/-scriptDebug`, `-cpuCount`,
  `-name` (отдельный профиль), список модов, необязательное прямое подключение
  (`-connect/-port/-password`), доп. аргументы и предпросмотр командной строки. У клиента нет
  собственного `-profiles` — DayZ сам решает, куда писать логи (см. ниже).
- **Сервер** — всё в одном месте:
  - пути (`DayZServer_x64.exe`, `serverDZ.cfg`, `-profiles`), сеть/производительность
    (`-port/-cpuCount/-limitFPS/-BEpath`), `-mod`/`-serverMod`, диагностические флаги
    (`-doLogs/-adminLog/-netLog/-scriptDebug/-filePatching/-freezeCheck`), доп. аргументы,
    предпросмотр командной строки;
  - **Конфигурация сервера** — быстрые поля для самых частых ключей `serverDZ.cfg` (hostname,
    password, maxPlayers, verifySignatures, forceSameBuild, disableVoN, disable3rdPerson/Crosshair,
    serverTime*, loginQueue*, instanceId, storageAutoFix и т.д.) плюс RAW-текст файла в
    сворачиваемом блоке — оба представления синхронизированы в обе стороны;
  - **Миссия** — список папок из `<сервер>\mpmissions` в виде переключателей (как выбор ветки):
    отметил — миссия сразу прописана в `template=` класса `Missions\DayZ`, отдельной кнопки
    «Применить» не нужно.
- **Логи** (отдельное окно) — переключатель Клиент/Сервер, список файлов `.RPT/.ADM/.log/.txt` и
  потоковый просмотр (tail) выбранного файла с автопрокруткой и фильтром по подстроке - фильтр
  применяется ко всему уже загруженному тексту, а не только к новым строкам. Текст окна следует
  теме (чёрный на белом теме, светлый на серой) - раньше был захардкожен как тёмная консоль, из-за
  чего на белой теме читался плохо. Окно не модальное — можно держать открытым и одновременно
  работать в основном окне.

  Папки логов по умолчанию (если поле Profiles сервера не заполнено):
  - Клиент Stable: `%LOCALAPPDATA%\DayZ`
  - Клиент Experimental: `%LOCALAPPDATA%\DayZ Exp`
  - Сервер: `<папка сервера>\profiles`

## Настройки программы (сворачиваемая панель под кнопками запуска)

- **Тема** — Серый / Белый.
- **Запускать клиент после запуска сервера** + **задержка (сек)** — при включении старт сервера
  через указанную задержку следом запускает и клиент.
- **Чистить логи клиента перед запуском** — перед стартом клиента удаляет `.RPT`/`.log`/`.ADM` из
  его папки логов (см. пути выше).
- **Чистить логи сервера перед запуском** — то же самое для папки логов сервера.
- **Вайпать сервер перед запуском** — удаляет папку `storage_1` (данные персистентности - базы, лут,
  positions) внутри `<сервер>\mpmissions\<текущая миссия>\`, где текущая миссия берётся прямо из
  `template=` в `serverDZ.cfg`. Необратимо - полный вайп сервера при следующем запуске.
- **Автоматически копировать ключи bikey на сервер при выборе модов** — срабатывает не при запуске,
  а сразу при добавлении мода через «+ Добавить мод»: если у выбранной папки есть подпапка `keys` с
  `*.bikey`, они тут же копируются в `<папка_сервера>\keys\`. `@Имя` из Workshop сюда не попадают -
  их ключи синхронизирует сам Steam.
- **Аварийная остановка клиент/сервер** + **сочетание клавиш** (по умолчанию `Ctrl+J`) — глобальный
  хоткей (работает, даже если фокус у самой игры, а не у DayZ Manager): мгновенно убивает все
  запущенные клиенты и серверы обеих веток. Чтобы поменять сочетание - кликнуть в поле и нажать
  новую комбинацию.

## Ограничения

- Автопоиск Steam проверяет только путь по умолчанию (`Program Files (x86)\Steam`) и его
  `libraryfolders.vdf` — нестандартные установки Steam ищутся вручную через «Обзор...».
- Быстрые поля конфига сервера покрывают ключи верхнего уровня из `serverDZ.cfg`; более сложные
  блоки (например, кастомные классы) редактируются через RAW-текст.
- Иконка приложения — `assets/app.ico`, замените файл, если нужна другая.
